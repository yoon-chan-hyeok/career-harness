# AI 실행 한도와 중단 복구

앱의 사용자별 실행량을 제한한다. **HF/Groq/OpenAI 계정의 잔액·무료 크레딧·실제 청구 제한을 조회하거나 보장하는 기능은 아니다.** 제공자 변경·유료 fallback·자동 재시도는 수행하지 않는다.

## 화면과 API 계약

모든 API는 기존 인증을 사용하고 인증된 사용자 자신의 장부만 읽거나 변경한다.

| API | 계약 |
|---|---|
| `GET /api/usage` | `limits`, `defaults`, `timezone: "UTC"`, `daily`, `monthly`, `account_balance_known: false`, `notice` |
| `GET /api/usage/limits` | `limits`, `defaults`, `notice` |
| `PUT /api/usage/limits` | 아래 6개 필드로 상한 교체. 응답은 `limits`, `defaults`, `notice`. 생략한 필드는 기존 값 대신 기본값을 적용하므로 화면은 6개 값을 함께 보낸다. |
| `GET /api/providers/activity` | 해당 사용자의 지원 작업에서 확인한 마지막 성공 `PromptRun`의 제공자·모델·시각·단계·지연시간과 현재 제공자·모델 일치 여부. 이 비교는 API 키/계정 변경이나 현재 연결 성공을 검증하지 않는다. 합성 연결 probe는 제외한다. 성공 기록이 없으면 `last_success: null`. |

기본값은 일 100회/월 1,000회, 일 200,000토큰/월 2,000,000토큰이다. `daily_calls`, `monthly_calls`, `daily_tokens`, `monthly_tokens`는 0~100,000,000 정수다. 0은 해당 AI 실행을 막는다. `daily_cost_usd`, `monthly_cost_usd`는 기본 `null`이며, 설정할 때는 0~1,000의 유한한 숫자를 받는다. 알 수 없는 필드·boolean 호출 수·NaN·음수는 거절한다. 일·월 상한을 모두 만족해야 한다. 직접 작성·수동 검수·AI를 사용하지 않는 승인에는 이 실행 한도를 적용하지 않는다.

`daily`/`monthly`의 `calls`, `tokens`는 **확정 차감과 임시 예약을 합친 장부 값**이다. 실제 실행 중인 HTTP 호출 수나 에이전트 진행률로 해석하지 않는다. `reserved_calls`, `reserved_tokens`는 아직 정산하지 않은 예약이고, `remaining_calls`, `remaining_tokens`는 예약을 빼고 남은 앱 실행 여유다. 토큰은 입력+출력 합계다. 실행 상태는 별도의 지원 작업 `/activity` 기록으로 확인한다.

## 예약·정산·재시작

AI 호출 전에 짧은 별도 DB transaction에서 사용자 장부를 잠그고 요청 단위 용량을 예약한다. 대화/다음 작업은 최대 5회, 검수는 3회 등 실제 흐름에 필요한 여유를 확보하며 호출당 토큰 예약 용량은 49,152를 기준으로 남은 일·월 한도 안에서 제한한다. 예약은 사용 예측이나 실제 진행 표시가 아니다.

각 호출은 입력의 보수적 추정치와 최대 출력 토큰을 이 예약에서 꺼낸다. 병렬 검수 두 작업도 같은 잠긴 메모리 예약을 공유한다. 네트워크 작업 중 별도 DB 연결을 빌리지 않아 SQLite의 쓰기 잠금과 서버리스 DB pool 1개/overflow 0 구성에서 교착을 피한다. 독립 예약 전에 이미 DB transaction을 보유하면 즉시 거절한다.

정상 종료·처리된 실패 후에는 업무 session의 commit/rollback이 연결을 반환한 뒤 정산한다. 유효한 응답 사용량은 실제 보고 토큰으로 차감한다. 사용량을 알 수 없는 실패·시간 초과 호출은 **시작한 호출의 입력 추정+최대 출력**을 보수적으로 차감한다. 시작하지 않은 호출·토큰 여유는 반환한다. 문서가 rollback되어도 실제 호출의 차감은 남는다.

프로세스 중단이나 정산 실패는 전체 예약을 그대로 남긴다. 중단된 `ExecutionRun`의 복구는 이 장부를 자동 환급하지 않는다. 현재 자동 환급·수동 예약 해제 API는 없다. 필요한 운영 정정은 원격 사용 내역과 실행 기록을 먼저 확인해야 한다.

일/월 버킷은 예약 시작 시점의 **UTC 날짜/월**로 정한다. UTC 자정에 새 일 버킷, UTC 매월 1일 자정에 새 월 버킷을 사용한다. 한국 시간으로 오전 9시다. cron으로 기존 기록을 삭제하거나 프로세스 재시작 때 사용량을 초기화하지 않는다. 지난 버킷과 중단 예약은 보존한다.

## 입력과 처리 시간

호출 전에 시스템 문장·사용자 JSON·실제 JSON schema를 포함한 UTF-8 바이트 수에 메시지 여유 256을 더해 토큰 수를 보수적으로 추정한다. HF 어댑터는 기본 입력 상한 32,768, Groq는 `8,000 - 최대 출력 - 256`을 적용한다. 단계별 더 작은 설정은 유지하고 무료 출력은 최대 4,096이다. 이 수치는 앱의 보수적 사전 정책이며, 모델 최대 context나 계정의 실시간 남은 토큰을 뜻하지 않는다. 복잡한 schema·긴 한국어 원문은 실제 tokenizer보다 크게 추정하여 거절할 수 있다.

대화 의도 판단에는 최신 문서 ID·버전·상태와 최근 4개 대화의 일부만 사용한다. 선택 문서 원문은 자르지 않으며 실제 작성·검수는 전체 승인 문서와 근거를 다시 읽는다. 화면의 `context_notice`로 이 선택을 알린다. 입력이 넘치면 문서/문항을 선택하거나 자료를 나누라는 안내로 중단하고 핵심 근거를 몰래 삭제하지 않는다. 응답 뒤 실제 사용량·완료 여부·schema·근거 검사는 계속 적용한다.

지원 워크플로 요청 deadline은 100초이고 단계·병렬 검수·역면접에 같은 마감 시각을 공유한다. 단계 기본 60초와 HTTP timeout을 남은 시간에 맞춘다. SDK/HTTP 호출의 실제 대기 시간도 제한하며 늦은 결과는 버린다. 최종 검증·DB·trace·승인 진행은 요청 thread에서 처리한다. 시간 초과는 upstream 요청 취소나 청구 취소를 보장하지 않으며, 계속 수행할 백그라운드 워크플로를 만들지 않는다. 화면은 110초 후 대기를 끝내고 저장 상태 재조회를 안내한다. 별도 연결 검사·경험 추출의 독립 scope도 DB 예약 전 100초를 시작하고 예약 지연만큼 후속 모델 시간이 줄며, DB 정산·ingress에도 별도 시간이 들 수 있어 모든 HTTP 응답이 100초 안에 도착한다고 보장하지 않는다. 응답 자체를 받지 못한 경우에도 현재 문서와 실행 기록을 먼저 재조회한다.

## 예상비용과 사실성 경계

가격은 서버의 명시적 `CAREER_LLM_PRICING_JSON`(기존 `OPENAI_PRICING_JSON` 호환)에서만 사용한다. 요청 장부는 남은 일·월 비용 여유를 임시 예약하고, 각 호출은 일반 입력·cached input·cache write 중 가장 큰 설정 요율과 최대 출력으로 계산한 보수적 금액이 그 예약 안에 드는지 확인한다. 사용하지 않은 비용 예약은 정산 때 반환한다. 임베딩은 출력 예약 0이며 입력 요율만 필요하다. 계산할 수 없는 가격을 0원으로 만들지 않는다. 비용 상한을 켰는데 필요한 요율을 모르거나 해당 기간에 미확인 비용 호출이 있으면 호출 전에 거절한다. 호출 수가 제한되지 않는 web tool 비용도 확실한 사전 상한으로 표현할 수 없어 비용 상한이 켜진 경우 거절한다.

`estimated_cost_usd`는 미확인 가격 또는 미정산 예약이 있으면 `null`이다. `known_estimated_cost_usd`는 장부에 금액으로 기록한 확정 차감·예약 부분을 보여주므로 예약 중에는 실제 사용 비용으로 해석하지 않는다. `unknown_cost_calls`와 미정산 예약을 함께 확인한다. 비용은 설정 요율과 보수적 예약으로 계산한 장부이며 제공자 청구서가 아니다. 비용 상한 미설정 시 `remaining_cost_usd`도 `null`이다.

`ai_usage_settings`, `ai_usage_buckets`, `ai_usage_reservations`는 `user_id`가 있는 운영 장부다. 설정·시간·숫자·예약 상태만 저장하고 프롬프트 원문·API 키·지원 문서·Fact/Ownership 승인을 만들지 않는다. ORM registry, 사용자 데이터 내보내기, Career DB 백업에 포함되고 PostgreSQL에서는 RLS 및 PUBLIC/anon/authenticated 직접 권한 차단으로 보호한다. 장부 변경·연결 probe·실제 AI 성공은 문서의 사실성이나 사람의 승인을 대신하지 않는다.

관련 검증: `tests/test_usage_limits.py`, `tests/test_request_budget.py`, `tests/test_runtime_trace.py`. 실제 제공자 잔액·운영 PostgreSQL·공개 ingress는 별도의 계정 연결 인수 검사다.
