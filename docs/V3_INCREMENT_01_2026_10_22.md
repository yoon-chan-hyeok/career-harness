# v3 첫 증분: 경험 읽기 모델과 실행 없는 계획 미리보기

기준 커밋은 `4202b86c079df28642e24e01d420664600bad316`이다. 사용자가 2026-10-22에 구현 시작과 GitHub 버전 관리 협업을 요청했다. 작업 브랜치는 `codex/v3-experience-shadow`이며 변경은 PR에서 검토한다. 이번 증분을 운영에 자동 배포하거나 main에 자동 병합하지 않는다.

## 범위

- ExperienceCard는 기존 Evidence/Source/DecisionEpisode/Ownership/Metric/ClaimBoundary를 읽는 projection이다. 새 사실 저장소를 만들지 않는다.
- RoleInterpretationProposal과 SectionTrace는 후속 구현의 데이터 계약이다. 직무 해석 생성·Persona 선택·문단 수정 UI를 완성한 상태로 표시하지 않는다.
- 규칙 선택/전달과 검사 결과를 구분한다. 기존 문장에 실제 기록 없는 규칙 적용 이력을 만들어 붙이지 않는다.
- ContextBudget은 입력과 출력 예약을 합한 정적 한도 계약이다. 실제 모델 요청을 아직 조립하지 못한 경로는 NOT_ESTIMATED로 두며 비용·공급자 가용량·전체 입력 문제 해결을 주장하지 않는다.
- 새 미리보기는 기존 작성 실행기와 분리한다. 자료·지원 상태 변경, 모델 호출, 승인, 잠금, 제출은 수행하지 않는다. 조회 함수는 SELECT만 실행하며 저장 대기 중인 세션은 거부한다. 공개 HTTP의 기존 인증·요청 한도 계수는 그대로 적용된다. 기존 결과는 재사용 후보일 뿐 완료 증명이 아니다.
- 9권 전체 원문·246 규칙은 이번 첨부 ZIP에 없었다. 새 규칙을 가져오거나 활성화하지 않는다. 개인 첨부 자료·실제 지원서·키는 공개하지 않는다.

## 다음 증분과 변경 수용

이 브랜치의 계약과 경계 검사를 먼저 확정하고, 이후 사용자 변경 자료에 맞춰 확장한다. 다음 작업은 실제 요청의 단계별 Context Compiler와 원문 버전 연결, Persona 선택 및 문항 하나의 생성·검수·설명 흐름이다. 새 엔진의 실행 어댑터는 기존 ready/freeze/confirm_submission 검증을 반드시 재사용한다. 비교·성능 개선 실험은 기존 사용자 결정대로 범위에 추가하지 않는다.

## 확인 방법

기본값은 `CAREER_V3_PREVIEW_ENABLED=0`이며 아래 경로는 404로 닫힌다. 별도 개발 환경에서만 `1`로 설정하면 기존 인증·동의·사용자 격리를 거쳐 조회할 수 있다. 운영 설정은 바꾸지 않았다.

| 조회 | 결과 |
|---|---|
| `GET /api/v3/experience-cards/{evidence_id}` | 공고 없이도 기존 경험과 출처·판단·기여·수치 기록을 버전 지문으로 묶어 조회 |
| `GET /api/v3/applications/{workspace_id}/plan-preview?intent=APPLICATION` | 등록된 문항과 요청 레쥬메의 단계·선행조건·승인·보관 후보 |
| 같은 경로의 `intent=RESUME_ONLY` | 자소서 생성·다문항 배분 없이 레쥬메 작성 계획 |
| 같은 경로의 `intent=INTERVIEW_ONLY` | 잠긴 제출 보관본 확인부터 면접 준비 계획; 보관본이 없으면 자료 대기 |

계획은 `SHADOW_ONLY`, `can_execute=false`, `completion_proof=false`를 반환한다. `READY`는 실행 전 검사가 필요한 후보이고 `REUSE_CANDIDATE`는 현재 저장 결과가 있다는 뜻이다. `NOT_APPLICABLE`은 선택한 요청에 없는 문서 종류나 단일 문항의 다문항 배분에만 쓴다. 자격·근거·전략 승인·주장 승인·최종 잠금·실제 제출 확인을 건너뛰었다는 뜻으로 쓰지 않는다.

같은 입력 버전과 요청은 같은 계획 ID를 반환한다. 경험·기여·연결 출처·문서 변경은 계획 지문을 바꾸며, 작업 노드 ID는 같은 범위에서 유지한다. 새 실행기·완료 증명·재시도 키를 구현한 것은 아니다. 레쥬메만 작성하는 계획도 기존 지원 전체를 제출 준비 완료로 바꾸지 않으며, 최종 보관은 기존 `ready()`가 등록된 전체 문서를 검사해야 한다.

현재 단계에서는 사용 가능한 실제 생성 입력을 조립하지 않으므로 AI 작업의 예산은 모두 `NOT_ESTIMATED`다. 규칙을 자동 선택하거나 사용자 자료를 외부 모델에 전송하지 않는다. 기존 `ㄱㄱ`와의 자동 비교 로그, 별도 Planner 화면, Persona 후보 생성·선택, 문단별 Trace 저장은 후속 증분이다.

## 롤백

아직 운영 미반영이므로 이 PR을 병합하지 않으면 현재 서비스에는 변화가 없다. 이후 병합해도 미리보기 기능 설정을 끄면 새 경로를 닫을 수 있게 한다. DB 마이그레이션 없이 추가하며, 이미 공유한 커밋은 삭제하거나 강제로 덮어쓰지 않고 필요한 커밋을 revert한다. 기준 커밋으로의 hard reset을 운영 롤백 절차로 사용하지 않는다.

## 검증

구현과 검증 결과는 IMPLEMENTATION_STATUS.json의 `v3_increment_01_2026_10_22`에 기록한다. 전체 Python 814개 통과, 별도 PostgreSQL 환경이 필요한 9개는 로컬에서 건너뛰었다. 관련 계약·조회·HTTP·기존 작성·SQLite 마이그레이션 40개, Ruff·Pyright·소스 개인정보 검사도 통과했다. 실제 PostgreSQL 및 프런트 빌드 결과는 PR의 원격 CI에서 확인한다.
