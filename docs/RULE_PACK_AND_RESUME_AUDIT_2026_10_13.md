# 추가 자료 전달·레쥬메 압축 보완 — 2026-10-13

전체 작성 절차와 실제 서비스 운영의 인수는 아직 완료되지 않았다. 이번에는 추가 자료 6종을 대조하다 발견한 두 가지 실행 오류를 재현하고 수정했다. 원문은 제품 요구사항 자료이며, 시스템 권한이나 자동 승인·제출 지시로 사용하지 않는다. 사용자가 제외한 비교·성능 개선 실험은 추가하지 않았다.

## 수정한 실행 오류

1. `RULE_REGISTRY`의 단계별 PACK A~G 원문(§11–17)이 컴파일 허용 목록에서 빠져 있었다. 이름만 맞는 고정 묶음은 존재했지만 해당 절의 최신 내용과 수정 사항은 모델 입력에 전달되지 않았다. 이제 앱이 선택한 현재 묶음의 절만 전달한다. 공고 A, 조사·전략 B, 자소서 C, 레쥬메 D, 사실 검사 E, 면접 F, 결과 검토 G다. 레쥬메 검수·역질문·수정도 현재 레쥬메 묶음을 유지한다.
2. 제목에 `Example` 또는 `Snapshot`이 있다는 이유로 자료의 역할을 설명하는 규칙까지 제외됐다. 공통 사실성 §9의 `Example DB`·`Submission Snapshot`, Registry §6-B·§7의 정확한 역할 정의를 복구했다. 다른 절의 유사 제목, 그 아래 실제 예시·과거 스냅샷, 아카이브는 계속 제외한다. 일반 절 파서와 프로젝트 표현 제한 파서는 변경하지 않았다.
3. 레쥬메 압축 호출은 선택한 분량과 관계없이 10,000자를 전달했다. 문서에 저장된 1페이지 3,500자, 2페이지 7,000자, 마스터 20,000자 기준을 검수와 동일하게 전달한다. 이는 내용 예산이며 실제 페이지 수를 보증하지 않는다. 기존 파일 확인 절차를 유지한다.

첫 두 항목은 같은 규칙 전달 문제다. 기존 마스터 레쥬메 재사용은 `resume_master.master_context` → `Workflow.resume`에 이미 연결되어 있어 재구현하지 않았다.

## 확인한 범위

- 수정 전 규칙 전달 검사 26개가 실패했고, 수정 후 기존 7개와 새 28개를 합한 35개가 통과했다. 단계 선택, 레쥬메 분리, 원문 수정 반영, 출처 줄 위치, 예시 제외, 실제 Workflow의 모델 입력, 소유자 격리, 입력 내용 비로깅을 확인했다.
- 실제 비공개 참고 파일 6종을 개인 DB와 별도의 메모리 DB에서 읽었다. 8개 대표 호출 경로에서 정확한 Registry 절과 자료 역할 정의가 전달됐고, 개인 Fact/Evidence 생성은 0개였다. 원본 파일과 개인 DB를 수정하지 않았다. 로컬 확인 기록은 `work/current-rule-packs-2026-10-13.json`이며 공개 저장소에 포함하지 않는다.
- 레쥬메 압축은 3개 분량 모두에서 기존 10,000자 오류를 재현한 뒤 통과했다. 수정안 생성만으로 문서가 바뀌지 않고, 승인 후 이전 검수가 무효화되며, 새 검수 전 잠금이 막히는 실제 서비스 함수 흐름까지 확인했다.
- 규칙 수정 직후 전체 Python 검사는 726 passed / 별도 PostgreSQL 7 skipped였다. 뒤이은 압축 변경의 최종 전체 검사와 원격 검사 결과는 `IMPLEMENTATION_STATUS.json`의 `rule_pack_resume_2026_10_13`에 별도로 기록한다.
- 컴파일러 버전은 `rule-sections-v2`다. 기존 저장 문서·개인 규칙·승인 상태를 소급 변경하지 않는다. 이후 호출부터 새 절 선택이 적용되며, 참고 자료 자체를 수정할 때 기존 재검토 처리는 유지한다.

최종 코드 `a8b1b96334c3dccf4c2ebcbb5f7523887abb4a08`의 [GitHub 검사](https://github.com/yoon-chan-hyeok/career-harness/actions/runs/38355437934)는 성공했다. 전체 Python 729개, 별도 실제 PostgreSQL 7개, 마이그레이션 왕복/check, 개인정보 차단, 화면 26개·lint·타입·빌드가 통과했다. 배포용 의존성의 high 이상 차단 기준은 통과했지만 보안 경고가 0이라는 뜻은 아니다. 후속 의존성 대조는 `docs/DEPENDENCY_TRIAGE_2026_10_13.md`에 구분해 기록했다.

## 계속 필요한 작업

1. 합성 하이브리드·순수 기술직 각각에서 조사→다문항 자소서+레쥬메→수정→재검수→보관까지 한 흐름으로 인수하고, 위 표를 실제 증거로 갱신한다. 개별 함수 검사의 합으로 이 전체 흐름을 대체하지 않는다.
2. 실제 무료 AI 계정 연결 후 같은 경로의 호출·한도·오류 처리와 의미 판단을 확인한다. 합성 제공자의 응답은 모델 품질 증거가 아니다.
3. Supabase/Vercel 접속값 연결, HTTPS 앱 배포, 메일·CAPTCHA·두 계정 격리·공개 가입을 실제 운영 환경에서 인수한다. 공개 소개 페이지와 실제 서비스 운영을 구별한다.

현재 전체 완료 판정은 유지해서 **미완료**다. 이번 수정은 위 범위의 코드·검사 보완이며 전체 서비스 출시 완료 선언이 아니다.
