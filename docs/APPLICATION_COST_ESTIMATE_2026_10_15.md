# Career Harness 작성 절차 비용 추정 — 2026-10-15

현재 크기의 입력을 유지할 때 새 회사 자소서 3문항, 문항별 1회 수정·재검수의 계산 기준은 **입력 500,000 / 출력 40,000토큰**이다. GPT-6.1 Sol 또는 Claude Sonnet 5.5 표준 단가로 약 **$1.40 / 1,960원**, 현재 Groq GPT-OSS 120B의 유료 단가로는 **$0.099 / 139원**이다. 가격 비교이며 품질 동등성·새 제공자 연결·유료 전환을 뜻하지 않는다.

## 실측과 추정을 구분

실제 격리 앱에서 성공한 회사 자료 추출 1회는 공급자 usage 기준 입력 **5,069**, 출력 **639**, 합계 **5,708**토큰이다. 무료 Groq 호출이므로 실제 유료 청구액을 의미하지 않는다. 앞선 로컬 입력 추정 6,562는 토크나이저와 안전 여유를 적용한 사전 검사값이다.

아직 실제 지원서 전체 절차의 사용량은 측정하지 못했다. 다음 표는 현재 호출 구조, 규칙·스키마 크기, 준비한 프로젝트 근거를 바탕으로 만든 예산 가정이다. 한 번에 50만 토큰을 보내는 것이 아니라 여러 호출의 반복 입력을 합친 값이다. 모델별 토크나이저 차이와 추론 길이는 실제 실행 후 교정해야 한다.

규칙과 응답 형식만 있는 로컬 사전 추정은 직무 분석 6,937, 전략 8,771, 초안 8,375토큰이다. 후보자 근거, 회사 자료와 이전 단계 결과는 여기에 추가된다. 준비된 프로젝트 3개 본문은 별도 로컬 토크나이저로 약 8,300토큰이다. 두 계산은 서로 다른 안전 여유 적용 여부를 가지므로 실측 청구량으로 더하지 않는다.

## 검색·규모·운영 예산

회사 검색을 OpenAI web search로 별도 5~10회 하면 도구비 **$0.05~0.10 / 70~140원**이며 검색 본문 입력 토큰은 추가된다. 위 입력 예산에 포함시킨 회사 본문은 다시 이중 합산하지 않는다. [공식 검색 가격](https://developers.openai.com/api/docs/pricing). 수동으로 확보한 공식 자료를 입력하는 경우 이 검색 도구비는 없다.

표준 Sol/Sonnet 전체 10개 회사는 모델 사용료 약 **19,600원**, 100건은 **196,000원**이다. 모델료에 30% 여유를 더하고 검색 10회($0.10)를 잡으면 1건 **2,688원**, 10건 **26,880원**, 100건 **268,800원**이다. 이는 상한 보장이 아니므로 실제 실행에는 호출·출력·총비용 제한이 필요하다. 모델료 외 서버/DB, 세금, 결제 환전 수수료, OCR·임베딩은 제외했다.

역할별 혼합 예시: 저위험 자료 정리에 Luna 입력 180,000 / 출력 12,000, 나머지 전략·글쓰기·검수에 Sol 입력 320,000 / 출력 28,000을 배분하면 **$0.944 / 1,322원**이다. 배분 가정이며 구현·품질 검증 결과가 아니다. 우선 동일 모델로 완주와 글 품질을 검증한 뒤 저위험 단계만 낮추는 편이 원인 비교에 유리하다.

## 현재 무료 운영 제약과 다음 판단

[Groq 공식 Free 한도](https://console.groq.com/docs/rate-limits)의 GPT-OSS 120B는 분당 8,000 / 하루 200,000토큰이다. 조직별 실제 한도는 계정 화면이 우선한다. 현재 앱도 이 무료 한도를 전제로 검사하므로 일부 단계는 요청 하나가 너무 크고, 표준 전체 합산도 하루 기준을 넘는다. 따라서 기다리기만으로 현재 전체 과정을 해결할 수 없다. 결제 전환만으로 앱 한도까지 자동 변경되지도 않는다.

현 시점 권고는 한국어 최종 글 품질 비교 후보로 Sol 또는 Sonnet을 두고 **회사당 약 3,000원** 예산을 마련해 전체 절차를 먼저 검증하는 것이다. 이 모델이 사용자의 실제 지원서를 이미 재현했다는 뜻은 아니다. 무료를 유지하려면 단계별 규칙 적용과 근거 선택을 줄이는 설계를 별도로 검증해야 한다.

새 유료 계정 연결·결제·다른 제공자로의 개인자료 전송은 수행하지 않았다. 실제자료 재현 검증은 회사자료 추출 1회 성공, 신규 자소서 0건이며 미완료다.

## 후속 검토: Luna + Sol 프롬프트 캐시

2026-10-15 공식 문서 기준 API가 제공하는 프롬프트 캐시는 공급자의 KV 재사용 기능이다. 입력 문맥 길이와 OpenAI TPM 계산 자체를 줄이지 않으며, 캐시 읽기 단가와 입력 처리 지연을 낮춘다. 출력 생성은 계속 별도 과금된다. [공식 동작·한도](https://developers.openai.com/api/docs/guides/prompt-caching).

[GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)는 입력/캐시읽기/캐시쓰기/출력 100만당 $0.10/$0.01/$0.125/$0.50, [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol)은 $2/$0.10/$2.50/$10이다. 쓰기 단가는 일반 입력 단가에 추가되는 금액이 아니라 해당 토큰에 적용되는 대체 단가다.

위 혼합 시나리오(루나 입력18만/출력1.2만, Sol 입력32만/출력2.8만)에서 두 모델에 같은 입력 토큰 적중률을 적용하고, 읽기 실패분 전부가 새 캐시 쓰기라고 보수적으로 가정하면 다음과 같다.

| 가정 | 총 모델료 |
|---|---:|
| 앞선 일반 입력 단가 기준, 캐시 읽기·쓰기 미반영 | 1,322원 |
| 캐시 읽기 0%, 입력 모두 새로 쓰기 | 1,552원 |
| 전체 입력 토큰 중 50% 캐시 읽기 | 1,000원 |
| 전체 입력 토큰 중 70% 캐시 읽기 | 779원 |
| 전체 입력 토큰 중 80% 캐시 읽기 | 669원 |

출력 예산은 그대로이며, 요청 적중 건수가 아니라 cached_tokens 합계 / input_tokens 합계다. 실제 요금은 일반 입력·캐시 읽기·캐시 쓰기 세 종류를 각각 집계해야 한다. 실제 재사용률은 미측정이며 70~80% 달성 약속이 아니다. 준비 호출만 추가하면 쓰기 비용이 늘 수 있으므로 불필요한 예열 호출은 권장하지 않는다.

현재 코드 확인:
- deterministic 자료 순서, 사용자 범위 cache key, 실제 응답 기반 cache usage 기록 및 cache-write 비용 계산은 존재한다.
- 규칙·자료·변경 문항이 단일 input 문자열에 함께 들어간다. 역할별 앞부분 지시문과 schema도 다르므로 역할 사이 자동 공유를 기대하면 안 된다.
- 캐시 비밀값이 별도 설정되지 않으면 process별 무작위 값으로 사용자 partition이 달라진다. 배포 환경의 안정적인 사용자 범위 식별값 적용 여부는 별도 확인이 필요하다. 실제 운영 비밀값은 이번 조사에서 읽지 않았다.
- OpenAI에서 실제 적중률 검증·새 캐시 설정·유료 호출은 수행하지 않았다.

추천 보완: 역할 지시문/규칙, 확정 근거/회사 자료, 현재 문항/수정 요청을 별도 메시지로 분리하고 동일 모델·동일 역할의 관련 요청에서 고정 앞부분을 유지한다. 사용자 격리와 규칙 버전 경계는 보존한다. Luna와 Sol 사이에 KV가 공유된다고 가정하지 않는다. 회사 분석 결과 자체의 저장·버전 확인·재사용으로 불필요한 호출을 줄이는 작업을 병행한다. [실제 적중률·쓰기량 진단](https://developers.openai.com/api/docs/guides/prompt-caching/diagnostics)으로 비용을 교정한다.
