# 작성 규칙 기반 전체 절차 구현 — 진행 기록

후속 2026-10-07 재점검: `RULEBOOK_V5_1_RECHECK_2026_10_07.md` 참조. 아래 최초 구현 묶음 뒤 F8 답변 처리 백엔드가 추가됐고 핵심 동작을 합성 검사로 확인했다. 사용자 화면·대화·면접 연결과 실행 앱 반영이 남아 있어 전체 구현 완료로 보지 않는다. 최신 회귀는 550 passed / 6 PG skipped, 진단 20개 중 9개는 남은 누락 재현이다.

## 범위와 현재 판정

사용자가 요청한 목표는 명세와 6종 규칙 문서를 기반으로 기존 GPT 취업 준비 절차를 앱에서 수행하는 것이다. 기존 기능·자료·승인·사실성 경계를 보존하고 명세의 모듈형 단일 백엔드와 Artifact 기반 상태 제어를 유지한다. **전체 완료는 아니다.** 아래는 검증을 마친 첫 구현 묶음이며, 이전 누락 감사의 재현 검사는 당시 상태를 설명하는 역사 기록이다.

비교·성능 개선 실험 제외, 무료 운영자 공용 AI, 초대형과 공개형 병행, 포트폴리오 설명은 이후 작업이라는 사용자 결정은 유지한다. 기존 실험 러너는 삭제하거나 우회시키지 않고 새 승인 전 검증 절차에 맞춘 합성 회귀만 수행했다.

## 이번에 구현하고 확인한 부분

| F4 설계 전 원자료 | 문항 설계에 원문, 현재 지표 원장, 확인된 판단 기록·수행 범위·금지 주장과 정제된 스타일을 전달한다. 여러 경험으로 하나의 메시지를 뒷받침할 수 있고 사용자가 선택한 주 경험은 유지한다. 전체 표현 문구 재사용은 F7 후속 범위다. |

문서의 지시문은 작업에 적용할 도메인 기준으로 취급한다. 시스템 권한·도구 권한·승인·개인정보·사실 검증을 대체하지 않는다. 예시의 숫자나 과거 개인 역량 스냅샷을 새 사실로 등록하지 않는다.

## 검증 근거

- 전체 Python 회귀: **550 passed, 6 skipped**. 별도 PostgreSQL 환경 검사 6개는 이번 실행에서 제외됐으며 과거 통과 기록과 구별한다. SQLite migration 왕복·기능·보안·격리 검사는 전체 실행에 포함된다.
- Ruff 전체 통과. 지정된 프로젝트 Python 환경으로 Pyright **0 errors, 0 warnings**. 처음 환경을 지정하지 않은 실행은 다른 Python 설치를 탐색해 import 오류를 냈으며, 프로젝트 환경을 명시해 해결했다.
- 프런트엔드 타입 검사·lint·production build 통과. 프런트엔드 기능 검사 **25 passed**.
- 실제 브라우저, 별도 합성 DB: 문항 선택 → 수동 원문 인용/4기준 입력 → 검증 저장 → 메시지 승인 → DB의 검증/메시지 LOCKED 확인. 초안은 승인만으로 자동 생성되지 않음. 390px 모바일에서 문서 너비 390px, 편집창 356px, 브라우저 오류 없음.
- 실제 6개 원문 모두 절 기반 해석 가능 상태 확인. 커버 문서의 규칙 절 73개 중 문항 설계에는 23개, 주장 검증에는 20개, 작성에는 25개를 선택한다. 이 수치는 요구사항 전체 구현률이 아니다.
- 일반 로컬 앱을 새 빌드로 재시작했다. 개인 DB를 합성 테스트 DB로 대체하지 않았다. 빌드 중 Windows가 실행 중인 프런트엔드 파일을 잡고 있어 실행 기록의 프로세스만 확인 후 중단하고 같은 빌드의 완료를 기다렸다.
- 증거: `work/rulebook-implementation-slice2-final.xml`, `work/rulebook-source-compilation.json`, `work/rulebook-ui-qa/result.json`, desktop/mobile PNG. `work/`는 커밋 제외 로컬 검증 자료다.

## 반드시 이어서 구현·확인할 범위

1. **조사와 Why Now(F2)**: 기본 진행에서 조사 상태/출처/수동 JD-only 한계를 명시하고 무료 AI 제공자와 독립된 조사 연결을 구현한다. 출처 없는 Why Now를 사실처럼 확정하지 않는다. 수동 JD-only 동작은 명세대로 유지한다.
2. **표현 저장·재사용(F7)**: 승인된 표현의 안전한 패턴을 보관하고 다음 문항에서 사용한다. 회사명·날짜·학력·수치·기여 등 사실은 제거하거나 현재 사실로 재검증한다. 원문 자소서를 그대로 Writer에 넣지 않는다.
3. **역질문과 보완 처리(F8)**: JD·본업·전략을 역질문 입력에 연결하고 질문-답변-근거 보완/문장 수정/면접 대비 등의 처리 상태를 버전에 묶는다. 미해결 검증 사항은 최종 잠금 전에 확인한다.
4. **전체 제출 검수**: Role Noun 판정, Red Team 지적의 처리 경로, 사실·숫자·결론·메시지 중복 검사와 문서 마지막 세 가지 준비 질문을 명시적인 결과로 연결한다.
5. **명세 전체 재대조**: 이번 감사의 F1–F8만으로 완료를 판정하지 않는다. 기존 구현 팩, 전체 커버 명세, 이력서 규칙과 6종 문서의 각 기능·불변조건·명령·산출물·게이트별 증거를 다시 확인하고 빠진 기능을 구현한다. 하이브리드 직무 전 단계와 이력서 병행 흐름을 합성 종단 검사한다.
6. **실제 운영 검증**: 현재 로컬 AI 설정은 미연결 상태다. 실제 무료 추론·인증·메일·DB·HTTPS·복구·내보내기 인수는 별도 확인이 필요하며 코드/합성 검사로 대신 완료 처리하지 않는다.
