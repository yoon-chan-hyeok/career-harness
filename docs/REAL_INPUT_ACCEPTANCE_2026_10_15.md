# 실제 입력 작성 인수 — 2026-10-15

판정: **미통과 / 최종 작성물 품질 미측정**. 사용자가 실제 과거 지원서와 비슷한 최종 결과를 요청해, 과거 3문항을 비교 전용으로 분리하고 실제 프로젝트 기록·6종 규칙을 격리 로컬 DB에 등록했다. 원본 지원서 답변은 모델 입력에 포함하지 않았다. 개인 원문·DB·프롬프트·결과는 gitignored `work/`에만 보관한다.

## 확인된 실행 장애

최초 회사 자료 추출은 외부 호출 전 `INPUT_TOKEN_BUDGET_EXCEEDED`로 실패했다. 아래 부분 수정과 사용자의 명시적 전송 승인 후 실제 Groq 재실행에 성공했다. 공급자 usage는 입력 **5,069** / 출력 **639** / 합계 **5,708**토큰, 실행 2.5초다. 성공 응답 1건이며 신규 자소서와 최종 잠금은 여전히 0건이다. 추출 응답의 현재 사업 소개를 과거 채용의 긴급성으로 확대하는 Why Now 추론은 채택하지 않는다.

1. 규칙 원문에 더해 절 번호·줄 위치·출처 해시 등의 감사용 탐색 정보까지 전송해 입력이 커졌다.
2. 무료 Groq 입력 여유를 계산할 때 응답 4,096토큰을 항상 예약해, 짧게 답할 수 있는 요청도 차단됐다.
3. 위 두 항목을 개선해도 일부 단계는 규칙 본문과 응답 스키마만으로 한도를 초과한다. 아직 전체 절차를 해결하지 못했다.

Groq 공식 문서의 무료 GPT-OSS 120B 한도는 분당 8,000토큰이며 실제 조직 한도는 계정 화면이 우선한다. [공식 한도 문서](https://console.groq.com/docs/rate-limits). 이 한도를 올리거나 유료 제공자로 전환하지 않았다.

## 로컬 수정

- `prompt_cache`: 알려진 컴파일 결과의 감사용 인덱스만 전송 형식에서 제외한다. 규칙 문자열·근거·권한 구분은 그대로 유지한다. 원본/인덱스는 저장된 컴파일 자료에 남으며, 원본 해시는 캐시 분리 기준으로 계속 사용한다. 알 수 없는 필드나 추가 규칙 텍스트는 삭제하지 않는다. 전송 형식 버전은 1.1.0이다.
- `compatible_providers`: 무료 총량 안에서 실제 입력 크기를 계산하고 응답 예약분을 조정한다. 기본 최소 1,024토큰, 사용자가 지정한 더 작은 출력 한도와 입력 제한을 존중한다. 여전히 큰 입력은 관찰 가능한 사전 검사에서 거부한다. 입력의 사실이나 규칙을 잘라내지 않고 자동 재시도·유료 대체를 하지 않는다.

이는 부분 수정이다. 원문 규칙을 온전히 전달하면서 전체 작성이 가능한 단계 분할/적용 범위 설계는 남았다. 이 변경을 배포하거나 전체 인수 완료로 표시하지 않는다.
