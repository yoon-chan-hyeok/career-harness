# 추가 작업·업그레이드 확인 — 2026-10-04

## 현재 결론

요청한 픽셀 작업실, 별도 관리자 화면, 최대 3개 경험 추천과 실제 작성 연동을 구현했다. 최신 코드의 운영용 frontend/backend Docker 빌드와 합성 데이터의 브라우저→API→저장 동작을 확인했다. 실서비스 전체 완료는 아니다. 실제 Hugging Face 작성, Supabase 운영 로그인·DB, HTTPS 배포, GitHub 업로드·원격 CI는 계정 연결 후 확인해야 한다.

이 문서가 추가 기능의 최신 기록이다. 기존 [필수 보완·6종 업그레이드](UPGRADE_PROGRESS.md)의 기능과 복구 검증은 유지된다. 사용자가 제외한 모델 비교·개선 실험은 추가하지 않았다.

## 이번에 반영한 기능

| 항목 | 실제 동작 | 검증 범위 |
|---|---|---|
| 픽셀 에이전트 작업실 | 여섯 역할의 캐릭터, 말풍선, 역할별 기록, 해당 문서 열기, 움직임 중지 | 실제 ExecutionRun·Artifact·PromptRun에서 상태와 메시지를 구성한다. 기록이 없으면 없다고 표시한다. 독립 에이전트끼리 대화하는 실행 엔진을 추가한 것은 아니다. |
| 경험 1·2·3안 | 현재 직무와 연결한 확인된 경험만 최대 3개. 추천 이유·원자료·공백·다른 문항 사용 표시 | 같은 경험의 중복 후보 제거, 부족하면 1~2개만 표시, 다른 계정의 근거 제외 |
| 선택의 작성 반영 | 선택 기록을 버전으로 저장. 전략/문항 메시지/이력서 경험 순서에 반영 | 이전 설계·초안 무효화, 바뀐 메시지 재승인, 실제 작성 입력의 선택 근거 확인. AI 입력 검사는 모의 제공자 테스트이며 실제 HF 응답과 구별한다. |
| 선택의 계승 | 전략에서 선택한 경험을 문항·이력서에서 이어받고 화면에 표시. 개별 글에서 다시 선택 가능 | 이어받은 선택과 개별 선택을 구별. 근거가 바뀌면 재선택 안내 |
| 별도 관리자 | 메뉴 및 `/#admin`, 현재 계정의 문서 수·승인 대기·실패·사용량·연결 상태·소스 링크 | 서버 권한 검사. 운영에서는 명시적 관리자 UUID만 허용. 일반 계정 403, 미로그인 401. 원문·키·다른 계정 자료 제외 |
| GitHub 코드 보기 | 관리자에 검증된 github.com 저장소 URL을 연결하는 자리 | 목적지 저장소가 아직 없어 실제 업로드·원격 CI는 미실행. 연결됐다고 표시하지 않는다. |

이번 검토에서 Supabase 관리자 메뉴 누락, 무효화된 선택 안내 누락, 전략에서 이어받은 선택 표시 누락, SQLite 실행 시각의 시간대 누락도 수정했다. 관리자 작업명은 내부 명령어 대신 한국어로 표시한다.

## 추가로 적용한 보완

1. 선택 근거와 추천 당시 버전을 저장하고, 오래된 후보로 저장하는 요청을 거절한다. 선택은 승인이 아니며 사용자의 검토를 건너뛰지 않는다.
2. 경험 재사용 횟수와 사용 문항을 표시한다. 같은 경험을 여러 글에서 쓸 수 있지만 사용 사실을 확인할 수 있다.
3. AI 역할 메시지는 실제 저장 기록에서만 만든다. 실행 기록 없는 대화나 가짜 작업 애니메이션을 생성하지 않는다.
4. Sharp 0.35.5·PostCSS 8.5.28로 실행 의존성을 보완하고 CI에 프로덕션 감사 단계를 추가했다.
5. frontend Docker를 다단계 standalone 이미지로 바꾸고 일반 사용자 `nextjs`로 실행한다. 개발 도구·전체 원본을 운영 runner에서 제외했다.

프로덕션 의존성 npm 감사는 확인 시점 경고 0개다. 전체 개발 도구 감사에는 수정 버전이 아직 없는 braces 관련 경고 5개가 남아 있다. 실제 새 runner에서는 eslint/braces/micromatch/fast-glob이 없음을 확인했다. 상세 근거는 [의존성 보안 기록](DEPENDENCY_SECURITY.md)에 있다.

## 최신 검증

- Python: **363 통과, PostgreSQL 전용 3개 제외**. 해당 PostgreSQL 3개는 앞선 실제 PG16/pgvector 환경에서 별도 통과했다. 이번 새 기능 검사가 운영 Supabase 검사를 대신하지 않는다.
- Ruff 통과, Pyright 오류·경고 0.
- frontend: lint·타입 검사, 인증 4개·배포 4개·업그레이드 9개 통과.
- 최신 production Docker 빌드 모두 통과. frontend UID 1001, backend UID 10001. backend migration head 0011, 현재 runtime Python 파일 SHA256 일치.
- 실제 built rewrite로 화면→backend 연결, 관리자 권한·사용자 격리 확인.
- 브라우저에서 3안 선택→ExperienceSelection 저장→이전 설계/초안 무효화→새 문항 설계에 선택 반영→승인 전 작성 차단 확인.
- 픽셀 6역할·실제 문서 메시지·움직임 중지·관리자 주소/재접속·일반 계정 차단 확인.
- 390px 관리자·작업실·문서 보관함의 문서 폭 390px. QA 소유자 화면의 JavaScript·콘솔·요청 오류 0.
- 개인정보 제외 검사 통과. 실제 개인 DB 대신 임시 합성 DB로 검증했다.
- 기존 개인 앱에도 최신 Windows standalone/backend를 반영했다. frontend 프록시의 관리자 접근·상태 200, 미인증/임시 QA 키 401, 기존 소유자와 활성 참고 규칙 6종 보존을 확인했다. 태스크가 만든 QA 컨테이너·네트워크·WSL 유지 프로세스를 정리했다.

로컬 재현 증거는 Git에서 제외한 `work/expanded-upgrades-qa/`의 `tests.xml`, source manifest, build 로그, `runtime.json`, `browser-acceptance.json`, 스크린샷, 리소스 정리 기록에 저장한다. 앞선 PDF/DOCX 다운로드·pgvector·백업/복원 증거도 보존한다.
