# 문서 간 사실·수치·반복 검수 — 2026-10-13

자소서 문항과 레쥬메의 같은 지표·사실·수행 범위를 비교하고, 검사 결과를 별도 버전으로 저장하는 기능을 추가했다. 운영 접속값과 실제 모델 연결을 기다리는 동안 수행한 작업이다. 전체 명세 충족이나 실제 AI·공개 회원가입 운영 완료를 뜻하지 않는다.

## 사용 흐름과 제출 조건

작업실의 **검수·제출 → 문서 간 사실·수치·반복 검사**로 현재 문서를 비교한다. 대화에서 **전체 문서 검수**라고 입력해도 같은 결과를 저장한다. 비교한 문서 이름·버전, 충돌 없음/확인 필요/수정 필요, 규칙 검사/AI와 규칙 검사 여부를 보여 준다. 일부 문서가 아직 없으면 전체 비교 미완료로 표시한다.

문제 발견 자체가 요청 오류가 되지 않도록 별도 검수 요청은 결과를 저장하고 반환한다. P0/P1 충돌이 남아 있으면 최종본 보관 준비와 실제 보관을 차단한다. 문서·근거·현재 작성 규칙이 바뀌면 이전 검사로 통과하지 못하며, 보관 체크리스트도 다시 확인을 요구한다. 검사 결과는 최종 제출 보관본에 포함된다. 기존 승인·문항/이력서 잠금·직업 정체성과 마지막 세 질문 확인은 유지하며, 다운로드와 보관을 실제 제출로 처리하지 않는다.

## 비교 범위

- 현재 확인한 지표 ID와 연결 경험을 기준으로 비교한다. 서로 다른 지표·측정 범위를 같은 숫자라는 이유만으로 충돌 처리하지 않는다. 기준값과 결과값을 구별한다.
- 쉼표·소수 표기와 명시적 시간/저장 용량 단위 등을 정규화한다. 인원·건수·기간·점수·비율을 비교하며, 날짜와 알려진 기술/모델 버전은 문항 반복 수치에서 제외한다.
- 같은 근거와 같은 사실 문장 구조의 단일 수치가 달라진 경우, 같은 경험의 단독 전체 구현과 AI 보조 구현이 충돌하는 경우를 검사한다. 단독 구현 주장은 그 Claim에 인용한 경험의 수행 범위와 대조한다.
- 같은 메시지, 유사 메시지, 정확히 반복한 사실 문장과 지표 ID를 검사한다. 자소서 문항 간 반복과 자소서/레쥬메 간 사실 일치를 구별한다. 같은 프로젝트를 다른 역할과 사실로 사용하는 것은 허용한다.
- 해당 사용자의 활성 작성전략 §5-4에 명시된 반복 금지가 있을 때만 정확한 사실·지표 반복을 P1로 처리한다. 다른 사용자의 규칙이나 규칙 속 예시를 후보자의 사실로 가져오지 않는다.

한 문장에 같은 단위의 여러 지표가 연결됐거나 범위/복합 값·불명확한 단위가 있으면 P2 원문 확인을 요청한다. 정해진 패턴과 구조화된 근거로 확인하는 검사이며, 모든 표현의 의미를 완전히 판정하는 기능은 아니다. 실제 제공자를 연결하면 현재 문서·근거·프로필·반복 규칙을 의미 검수에 함께 전달한다. 모델의 문제가 없다는 응답이나 수동 PASS가 규칙 검사 충돌을 지우지 못한다.

## 검증 기록

새 수치/문서 비교와 저장 검수의 합성 검사 31개를 추가했다. 기존 다음 단계·마지막 확인과의 충돌 두 건은 제품 동작을 수정해 해결했다. 최신 전체 백엔드 및 원격 검증 결과는 IMPLEMENTATION_STATUS.json의 document_consistency_2026_10_13에 기록한다.

프런트 검사 26개·lint·typecheck·production build, Ruff 및 Pyright를 통과했다. 별도 실제 브라우저에서 잠근 가상 자소서 3개/레쥬메 4개의 충돌 저장 → 정정 후 이전 결과 재검토 → 레쥬메 2차 기준 검사 2차 통과 → 보관 준비 → 불변 최종본 보관을 확인했다. 화면 프록시로 다시 조회한 보관본에도 최신 검사와 레쥬메 버전이 포함됐다. 390px 모바일 가로 넘침과 브라우저 경고/오류는 없었다. 개인 자료·키를 이 합성 검증에 사용하지 않았다.

실제 개인 작업실의 기존 인증과 자료 읽기·잘못된 토큰 거부는 별도 확인한다. 실제 AI는 여전히 미연결이며, 문장 생성/의미 검수의 실서비스 품질을 합성 제공자 검사로 보증하지 않는다.
