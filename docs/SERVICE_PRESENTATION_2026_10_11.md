# 서비스 소개·모션 데모 — 2026-10-11

사용자가 제품 형태와 GitHub 소개를 먼저 완성하도록 순서를 바꿨다. 이후 소개 페이지와 GitHub 소스의 공개 전환을 직접 승인했다.

## 제공하는 경험

- 메인 `/`는 로그인이나 API 호출이 필요 없는 소개 페이지다. 기존 보라색을 유지하고 문제·사용 흐름·설계 원칙·자소서와 레쥬메·시작 방법을 설명한다.
- 실제 작업실은 `/workspace`로 옮겼다. 기존 인증·자료·승인·보관 동작은 유지한다.
- 6단계 체험은 공고 분석 → 근거 연결 → 전략 승인 → 작성 → 검수·수정 → 최종본 보관을 보여 준다. 단계 선택, 자동 재생·일시 정지, 화면을 떠날 때 정지, 동작 줄이기 설정을 지원한다.
- MP4는 약 29초·1280×800·무음이며, GitHub README는 GIF 미리보기와 같은 영상 링크를 제공한다. 모두 가상 자료다. 실제 사용자나 AI 응답으로 오인하지 않도록 표시한다.
- 별도 정적 소개 사이트는 개인 계정·AI 호출·자료 저장 기능을 포함하지 않는다. 공개 가입과 AI 서비스가 이미 운영 중이라고 표시하지 않는다. 실제 작업실 연결 전에는 실행 방법을 안내한다.
- README는 서비스 목적, 사용자 흐름, 설계 이유, 로컬 실행, 구조와 현재 한계를 중심으로 다시 썼다. 기존 구현 팩 안내는 보관했다.

## 구조와 배포

`frontend/public/showcase`의 HTML/CSS/JavaScript가 소개의 원본이다. Next.js 루트 정적 응답과 별도 소개 사이트가 이를 함께 사용한다. 새 대형 런타임 의존성은 추가하지 않았다.

`scripts/prepare-showcase-site.mjs`는 명시한 소개 자산만 별도 등록된 Site 디렉터리로 복사한다. 개인 자료를 읽지 않고, 공개 소개의 작업실 링크를 실제 서비스인 것처럼 연결하지 않는다.

## 확인한 범위

- 프런트엔드 lint·타입 검사·최적화 빌드, 기존 회귀 26개 통과.
- 실제 브라우저에서 6단계 선택, 자동 재생·정지, 수동 선택 시 정지, 동작 줄이기, 390px 모바일 가로 넘침 없음.
- 새 `/workspace`에서 격리된 합성 계정으로 최종 확인 → 보관 → 면접 자료 연결 통과. 개인 자료·실제 AI를 사용하지 않았다.
- Ruff 통과, Pyright 오류·경고 없음. 백엔드 제품 코드는 변경하지 않았다.
- 공개 대상 파일과 기존 10개 커밋에서 개인 경로·기존 로컬 키·자격증명 패턴 검사 통과. API 키·DB·개인 원문·로컬 설정은 제외한다.
- 기존 백엔드 642개·별도 PostgreSQL 6개 통과는 10월 10일 기준이며, 이번 소개 변경의 GitHub CI는 별도 실행 기록으로 확인한다.

## 남은 범위

실제 AI, 운영 인증·메일·CAPTCHA·DB, 공개 가입 서비스의 전체 인수와 복구 검증은 남아 있다. 소개 페이지 공개를 전체 서비스 운영 완료로 간주하지 않는다.

프로젝트별 표현 제한·반복 검사·원문 전체 인수도 아직 완료되지 않았다. 중단 직전 작성하던 표현 제한 초안은 로컬 `work/pending-boundary/project_boundaries.py`에 보존했고 제품 코드에는 연결하지 않았다. 비교·성능 개선 실험 제외는 유지한다.
