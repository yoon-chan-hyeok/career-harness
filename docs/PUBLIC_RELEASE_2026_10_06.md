# 공개 가입형 구현·검증 기록 — 2026-10-06

사용자의 “초대 규모가 아닌 버전도 추가, 퍼블리싱 가능한 수준” 요청에 따라 공개 가입형을 추가했다. 기존 초대형과 개인 로컬 모드는 보존한다. **공개형 코드와 배포 설정이 준비된 상태이며, 실제 외부 공개 운영 인수는 남아 있다.**

## 추가된 동작

- `CAREER_ACCESS_MODE=public`: 초대 명단 없이 Supabase 이메일 OTP로 가입한다. `invite`가 기본값이다. 공개 설정에는 허용한 항목만 노출한다.
- 보라색 기존 팔레트의 공개 첫 화면, 이메일 코드 입력, 개인정보 처리방침·약관 페이지, 가입 중단 안내를 추가했다. 작성 작업실은 기존 대화·오른쪽 문서 보관 구조를 사용한다.
- 서명 검증과 비익명 계정 확인, 최초 가입 시 실제 Auth `/user`의 이메일 확인 상태를 검사한다. CAPTCHA 토큰을 Supabase에 전달하고 재발송 간격을 둔다.
- 현재 정책 버전에 동의하기 전 작업실 API를 차단한다. 동의하지 않은 사람도 계정 관리·자기 자료 내보내기·삭제에 접근한다.
- 새 계정의 기본 AI 상한은 하루 10회·월 100회와 토큰 상한이며, 기존 공용 상한도 함께 적용한다. 이는 제공자 호출 수다. 한 작성 작업에서 여러 호출을 사용할 수 있다.
- 계정 UUID별 요청/변경 요청 한도는 PostgreSQL의 원자적 장부로 처리한다. 지원·근거·원자료·문서 개수 상한과 기존 업로드 용량 한도를 함께 적용한다.
- 운영 회원 목록을 50개씩 조회하고 ID로 검색한다. 사용자 문서를 회원 목록에 공개하지 않는다.
- 탈퇴는 같은 계정의 최근 OTP와 DELETE 확인을 요구한다. 접근 차단 → 취업 자료·벡터 삭제 → Auth 계정 삭제 순서로 처리한다. 외부 장애 시 접근 차단을 유지하고 재시도 상태를 남긴다. 뒤늦게 끝난 작업은 최종 저장 때 다시 계정 상태를 확인한다.
- 최소 접근 차단 기록·사용량·삭제 처리 기록은 보존한다. 실제 백업 만료와 복원 시 삭제 재적용은 운영 절차로 명시했다.
- migration 0013에서 요청 제한 테이블과 Supabase Data API 권한 차단을 추가했다. 서버리스 초기화가 DB 설정 검증 전에 로컬 설정을 읽지 않도록 설정 의존성을 분리했다.

## Astra 재검토

추가된 인증·가입·탈퇴·요청 제한과 프런트 연결 코드를 읽고 재현 검사를 수행했다. 확인된 P2 두 건을 수정했다.

1. 시작 단계와 탈퇴 실행 단계에서 키 종류/환경변수 검사 기준이 달랐던 문제: 공통 검사 함수로 통일하고 6개 회귀 경우를 추가했다.
2. 인증 만료 후 동의·계정 관리 화면 상태가 남던 문제: 인증 갱신 실패와 HTTP 401 양쪽에서 해당 상태를 초기화한다.

Astra가 수정 후 키 조합 4개·화면 상태 4개를 다시 검사해 모두 통과했다. 보고서는 `work/public-release-astra-audit.md`에 있다. 외부 운영 인증이나 전체 소프트웨어 보안 인증을 의미하지 않는다.

## 실제 공개 전 남은 일

1. 실제 서비스명·운영자·문의 이메일·백업 기간과 처리 안내 확정. 공개 화면에 임의의 운영자 연락처를 넣지 않았다.
2. Supabase 운영 DB/TLS/Auth, 실제 SMTP와 OTP 템플릿, Turnstile, 서버 전용 삭제 키 구성 후 테스트 계정 두 개로 가입·격리·탈퇴 확인.
3. 운영자의 무료 AI 계정·키를 연결하고 실제 문서 응답과 한도 장부 확인. 현재 개인 로컬 제공자는 `none`, 실제 AI 검증은 false다. Jev 실호출도 주장하지 않는다.
4. 소스 공개 전 개인정보 검토와 원격 CI, 실제 Vercel HTTPS 배포, 호스팅 플랜 조건 확인.
5. 실제 백업 복구·삭제 요청 재적용·장애 알림·호스팅 입구 제한과 예상 트래픽 부하 확인. 무료 인프라의 지원 인원이나 무제한 사용을 보장하지 않는다.

배포 순서는 [공개 서비스 설정](PUBLIC_SERVICE_SETUP.md), 설정 예시는 `deploy/public-access.env.example`을 따른다. 비교/성능 향상 실험은 사용자 결정대로 제외했다. 포트폴리오의 설계 의도·RAG·Jev 설명 페이지와 실제 Word 페이지 렌더 검증은 이전과 같이 후속 작업이다.
