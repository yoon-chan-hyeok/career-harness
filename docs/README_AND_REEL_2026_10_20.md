# README 현황 대조와 세로 소개 영상 — 2026-10-20

## 대조 결과

README는 기능·실행법·운영 한계를 설명하고 있었지만, 사용자가 반복하던 판단을 어떻게 구현했는지가 추상적이었다. 사용자 흐름은 표에만 있었고 구조도는 서버 간 연결을 보여 주었다. 이번에는 판단 사례 → 사용자 흐름도 → 확인된 기능과 미완료 범위 순서로 읽을 수 있게 보완했다.

범위는 README와 대표 구현 경로의 대조, 개선 우선순위 정리, 공개 가능한 소개 영상 제작이다. 전체 코드 재감사나 새 운영 인수를 완료한 기록이 아니다. 사용자 결정에 따라 비교·업그레이드 실험은 제외한다.

| 확인한 항목 | 코드·기록의 근거 | README 반영 |

## 남은 개선 순서

다음 항목은 작업 제안이며 이번 영상 제작으로 구현된 기능이 아니다.

| 우선순위 | 할 일 | 끝났다고 판단할 기준 |
|---|---|---|
| 1 | 전체 작성 단계의 입력 한도 해결 | 전략·문항 설계·작성·검수에 필요한 사실과 규칙을 보존하며 실제 공급자 한도 내 실행. 원문을 몰래 잘라내거나 자동 유료 전환하지 않기 |
| 2 | 개인 지원서 한 건을 끝까지 인수 | 승인된 자료로 조사 → 근거 → 전략 → 문항별 설계 → 생성 → 검수·수정 → 글자 수 → 잠금. 원래 답변은 비교 전용으로 두고 판단·사례·기여·수치·문장 품질을 확인 |
| 3 | 단계별 응답 지연과 실패 안내 점검 | 요청별 시간·실패 위치·재개 상태 확인. 기존 공개 검증의 35개 직렬 요청 총 401초를 문항 1회 지연으로 오인하지 않기 |
| 4 | 운영 DB 복구와 삭제 재적용 훈련 | 별도 환경 복원, 데이터·벡터·소유권 대조, 삭제 요청 재적용 확인. 로컬 복구 성공으로 운영 복구 완료를 대신하지 않기 |
| 5 | 원문 가이드 확대 | 출처·재사용 범위·회사/직무/문항/제한 조건을 검수. 구조 제안과 실제 지원서 예시를 구분 |
| 6 | 상태 문서의 현재 요약과 과거 이력 분리 | IMPLEMENTATION_STATUS.json의 일부 누적 verification 항목과 날짜별 보고를 현재 완료 판정으로 혼동하지 않도록, 최신 소스·CI·운영 인수·미통과 조건을 한 곳에 모으기 |
| 보류 | 이메일 인증·발송, Jev, 유료 모델 | 사용자가 다시 요청할 때 계정·운영 조건 확인. 현재 완료로 표시하지 않기 |

성능·합격률 개선을 입증하는 비교 실험은 위 목록에 포함하지 않는다. 기능 정확성·사실 경계·소유권·저장·복구 확인은 계속 필요하다.

## 영상

- 길이 40초, 1080×1920, 9:16, 30fps, H.264 / AAC, MP4 faststart.
- 보라색·밝은 라일락·짙은 잉크색, 큰 한국어 제목, 카드 순차 등장, 방향 전환선, 진행 막대.
- 소리는 외부 음원 없이 직접 합성한 120 BPM 비트다. 음성을 듣지 않아도 핵심 정보가 화면에 남는다.
- 실제 구현된 판단 원칙을 가상 공고·경험으로 재구성했다. 개인 지원서 문장·연락처·DB·자격증명·실제 AI 응답을 넣지 않았다.
- 600자 70/120/280/130 구성은 [기존 공개 가이드](../backend/career/assets/writing_guides/posco_dx_technical.json)의 내용별 권장 배분이다. 새 성과 수치나 모든 문항의 고정 템플릿이 아니다.
- 공개 게스트 체험이 있으며 전체 개인 자료의 AI 작성 품질은 검증 중이라는 한계를 마지막 장면에 표시한다.
