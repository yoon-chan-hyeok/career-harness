# mini-kit 적용 가능성 검토 — 2026-10-17

판정: **현재 Career Harness에 적용 가능하며, 초안 설계·예시 활용을 보완하는 자료/UI 기능으로 채택할 가치가 있다. 기존 앱에 붙이는 어댑터와 상태 관리는 필요하다.** 사용자 요청은 적용 가능성 확인이며, 첨부 안내문의 구현 순서는 평가 대상인 제안으로만 읽었다. 앱 기능 구현·배포는 수행하지 않았다.

## 검토 범위

입력 ZIP: career-harness-mini-kit.zip. SHA-256: 886b1490fb389e62cdf279e50f42cb393fc038bfe0a7aeae3fd2dced19991bbb.
파일은 example-data.json, draft-screen.html, service-integration.md 세 개이며 실제 데이터는 포스코DX SW 개발 전문역량 600자 문항 **1건**이다. 파일의 문자 인코딩은 정상 UTF-8이다.

HTML은 시각화 도구의 iframe·상태 저장 래퍼를 포함한 독립 시안이다. 원문 HTML·JSON과 해당 역할의 코드만 검사했다. 브라우저 실제 렌더링·모바일 시각 검사는 수행하지 않았다. 추출한 앱 로직을 외부 접근 없는 테스트 DOM에서 검사했고 실제 모델을 호출하지 않았다.

전체 877문항 DB, 유사 문항 판정기, 생성 API, 사용자 자료 영구 저장 기능은 없다. 제공된 semantic_reviewed 등의 표식은 자료 작성자의 메타데이터이며 우리 서버의 승인 기록으로 자동 승격하지 않는다.

## 그대로 붙일 수 없는 부분

1. 정적 HTML을 프로덕션 iframe으로 삽입하는 대신 현재 Next.js 대화/오른쪽 보관함 안의 React 패널로 옮기는 편이 맞다. 시각화 래퍼, window.openai, CDN 아이콘/보조 라이브러리는 앱 기능에 필요하지 않다.
2. JSON을 현재 /draft API에 그대로 전송할 수 없다. 기존 Writer는 ApplicationBrief/QuestionBrief 잠금, Evidence Test 통과, 현재 근거 버전, ClaimLedger를 요구한다. 이 절차를 보존한 채 가이드 문맥을 추가해야 한다.
3. 예제 textarea의 applicant_facts는 user_entered_preview_only다. 입력 문자열이 존재한다는 조건만으로 확인된 경력 사실로 인정하면 안 된다.
4. 예제의 active 페르소나는 demonstration_only_not_applicant_fact다. 최초 사용자 전략으로 자동 채택하지 않는다. 미사용은 생성에서 제외, 폐기는 실제 저장 내용 처리와 입력 무효화를 서버에서 수행해야 한다.
5. 원문 600자 제한과 배분은 해당 원문 문항용이다. 다른 회사·문구·필수 요구·분량이 다른 질문에 그대로 적용하지 않는다. 문항의 명시 조건 > 작성 가이드 권고 순서를 유지한다.
6. 기존 hard_qa는 Python len(text)로 상한을 검사한다. 키트는 공백/제목 포함·줄바꿈 제외한 보관 원문 계산을 사용하고 현행 공식 카운터는 미확인이다. 현재 지원서의 문자/바이트·공백·줄바꿈 조건을 명시한 서버/화면 공통 계산기가 필요하다.
7. source_paragraph_sha256는 포함된 source_quote의 해시와 일치하지 않는다. 원문 문단 전체를 해시한 값일 수 있어 훼손이라고 판단하지 않는다. 해시 대상 원문 전체와 계산 규칙을 함께 보관하기 전에는 이 문단의 무결성 검증 완료로 표시하지 않는다.
8. 예시 전문의 공개 노출을 확대할 경우 출처 표시와 발행처 이용 조건을 확인한다. 공개 사용 허락 여부는 이번 로컬 검토에서 판정하지 않았다.

## 실제 확인

- 화면 가이드와 generation_context의 가이드가 같은 값이다.
- 화면 규칙과 생성 규칙이 같다.
- HTML 안의 UI·생성 입력·게이트는 JSON과 같다.
- 가이드 스냅샷 SHA-256은 UTF-8, 키 정렬, 공백 없는 JSON 직렬화로 정확히 재현된다.
- 예시 제목15 + 본문278 + 본문299 = 592자. 세 부분의 글자 수와 SHA-256이 모두 일치한다.
- 권장 배분70 + 120 + 280 + 130 = 600자이며, 예시 본문은 2문단이다. 내용 기능4개를 문단4개로 강제할 이유가 없다.
- 미확인 입력의 preview 상태 유지, 가이드 동일성, active/unused/discarded의 생성 포함 여부, 변경 시 준비 입력 무효화, revision 증가, 폐기 후 자동 재활성화 차단 등 **격리 로직 검사11개 통과**.
- 이 검사로 실제 AI 작성 품질, DB 영구 저장, 사용자 격리, 브라우저 렌더링 완료를 주장하지 않는다.

## 토큰 영향

동봉된 오프라인 o200k 계열 토크나이저로 compact JSON을 계산했다. 모델 청구량·실제 호출값이 아니다.

| 선택 가이드1건 전체 | 1,506 |

| 예제 generation_context | 1,803 |

실제 요청에는 선택된 가이드 한 번만 포함한다. UI는 필요할 때 같은 서버 자료를 렌더링하면 된다. 이 키트 자체가 현재 무료 Groq의 입력한도 문제를 해결하지는 않는다. 기존 규칙에 무조건 추가하면 오히려 입력이 늘어난다. 가이드 버전과 개인 동적 근거를 나누는 캐시 설계에도 맞출 수 있으나 실제 적중률은 미검증이다.
