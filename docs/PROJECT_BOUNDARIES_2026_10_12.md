# 프로젝트별 표현 제한 연결 — 2026-10-12

작성전략 §10의 프로젝트별 강조점과 금지 주장을 실제 경험·문항 검증·자소서·레쥬메 작성 흐름에 연결했다. 추가 구현은 운영 접속값 입력과 독립적으로 수행했다. 전체 작성전략 충족이나 실제 AI 운영 완료를 의미하지 않는다.

## 사용 흐름

경험 정리에서 경험을 펼친 뒤 **프로젝트 표현 제한**을 연다. 현재 활성 작성전략의 프로젝트 절과 정확한 원문·행 범위를 읽고 적용할 규칙을 고른다. 같은 이름의 프로젝트는 선택 후보로 보여 주지만 자동으로 연결하지 않는다. 원문과 경험을 직접 대조한 확인 체크가 있어야 저장한다. 해당 경험에 적용할 규칙이 없다는 선택도 직접 확인으로 기록한다.

확인한 경험과 원문 버전에 연결 기록을 묶는다. 경험 본문·수행 범위 데이터·검증 상태가 바뀌면 재확인을 요구한다. 연결한 규칙의 원문 버전·활성 상태가 바뀌어도 재확인이 필요하다. 원문이 바뀌었는데 이전 연결을 그대로 승인된 것으로 사용하지 않는다.

연결을 추가·변경하면 그 경험을 사용한 현재 결과와 그 결과에 의존하는 문서를 재검토로 바꾼다. 같은 원자료를 공유하더라도 다른 경험만 사용하는 결과, 다른 사용자의 결과, 불변 제출 보관본은 변경하지 않는다. 반복 저장은 동일 연결의 새 버전을 불필요하게 만들지 않는다. PostgreSQL에서는 경험 행 잠금으로 동시 확인을 직렬화한다.

## 사실과 작성 규칙의 분리

규칙 원문은 표현 제한·강조점의 자료다. 규칙 속 예시·수치·과거 성과를 후보자의 Fact로 등록하지 않는다. 실제 작성 근거는 여전히 확인된 경험·현재 사실·지표·수행 범위다. 추가 규칙의 텍스트로 권한이나 승인 조건을 바꿀 수 없다.

연결한 원문은 해당 경험의 문항 설계·Evidence Test·작성·사실 검수 문맥에 함께 전달된다. 자소서와 레쥬메 모두 같은 연결을 읽으며, 규칙 출처를 문서 의존성에 포함한다. 일반 Resume 규칙과 프로젝트별 제한을 구별한다.

현재 명시적 검사 대상은 원문에 해당 금지가 있을 때의 전체 시스템 개발 확대, Agent 구축 확대, 실제 서비스 배포 성과, 정식 FAR/FRR 개선, 측정한 운영 시간·비용 절감이다. 연결된 경험의 Claim에만 적용한다. 수동 PASS 표시로 검사를 덮을 수 없으며, Evidence Test·본문 검수·최종 잠금에서 확인한다. 부정·계획·희망·적용 가능성과 실제 성과 주장을 구별하는 회귀를 포함한다.

이 검사는 정해진 패턴에 대한 검사다. 가능한 모든 표현의 의미를 자동 판정하는 기능은 아니다. 나머지 강조점과 의미상 과장은 원문 대조 및 기존 사실/수행 범위 검수로 확인해야 한다. 실제 모델 품질을 이번 합성 검증으로 보증하지 않는다.

## 연결 인터페이스

- REST: 경험별 `project-boundary` 조회·명시적 확인 저장. 사용자 소유권, 현재 해시, 엄격한 확인 타입, 활성 원문을 검사한다.
- 웹: 경험 정리의 펼침창에서 조회·선택·원문 대조·확인·저장. 펼쳤을 때만 조회하며, 선택을 바꾸면 확인 체크를 해제한다.
- MCP: `career_project_boundary`로 현재 규칙과 확인 상태를 조회한다. 기존 MCP의 읽기 전용 원칙을 유지한다. MCP 읽기 도구는 4개이며 원격 ChatGPT 프로젝트 연결이나 쓰기·승인 MCP 완료를 주장하지 않는다.

## 검증

- 새 기능의 SQLite·API·규칙·격리·변경 전파·생성 문맥 검사 25개. 기존 원문·문항·작성 흐름과 실제 stdio MCP를 포함한 최종 관련 검사 50개 통과.
- 넓은 로컬 회귀는 최초 추가 22개를 포함해 Python 664개 통과/PG 6개 생략. 이후 3개 계획·희망 표현 사례와 PG 동시 확인 검사를 추가했다. 최신 전체 회귀와 실제 PostgreSQL 동시 확인 결과는 GitHub 자동 검사에서 별도로 확인한다.
- Ruff 통과, Pyright 오류·경고 0개. 프런트 검사 26개·lint·typecheck·production build 통과. 화면 안내·라벨 개선 후 lint/typecheck/build 재확인.
- 실제 합성 브라우저: 확인 전 저장 차단 → 선택 변경 시 재확인 → 저장 → 재조회한 연결 유지 → 관련 근거 매핑 재검토 확인. 최신 화면에서도 저장 확인. 390px 모바일 가로 넘침·경고·오류 없음.
- 기존 개인 작업실: 기존 로그인과 자료 읽기, 잘못된 토큰 거부, 새 API와 프런트 프록시 통과. 현재 실제 등록 자료에서 프로젝트 절 5개·명시적 검사 5개를 조회했다. 본인의 프로젝트 연결을 자동 승인하거나 변경하지 않았다.
- 합성 검증용 API·화면 프로세스는 ID·시작시각·실행 경로·포트를 확인하고 종료했다. 가상 DB와 화면 증거는 비공개 작업 폴더에 보존했다. 기존 개인 작업실을 새 버전으로 다시 실행했다.

Windows에서 실행 중인 standalone 화면이 빌드 폴더의 native 파일을 잡고 있어 빌드가 대기했다. 확인한 화면 프로세스만 종료해 빌드를 완료했다. 합성 복제 환경의 이전 `route-cache`도 남아 있어, 해당 합성 폴더 안의 경로와 링크 여부를 확인하고 캐시만 정리한 후 실제 제공된 화면 파일이 최신 빌드와 같은지 확인했다.

## 이어서 할 작업

문서 간 일반 수치·사실·수행 범위 충돌과 문항별 사실·숫자·유사 메시지 반복 검사를 강화한다. 26단계와 원팩·6종 참고 자료의 전체 인수도 남아 있다. 실제 AI 호출, 운영 HTTPS·회원가입·SMTP·CAPTCHA·백업 복원은 별도의 운영 연결과 검증이 필요하다. 비교·개선 실험 제외 결정은 유지한다.
