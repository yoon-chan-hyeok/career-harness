## 이번에 구현한 변경

### 초대 전용 소규모 운영

- 실제 JWT 검증 후 매 요청에서 초대 상태를 확인한다. 승인 목록이 비어 있으면 접근을 거절한다.
- 운영자가 이미 생성된 Supabase 사용자의 UUID를 승인·중지하고 개인별 한도를 설정한다. Auth 계정 생성이나 초대 이메일 전송 기능은 아니다.
- 중지한 계정은 기존 JWT를 사용해도 다음 요청부터 거절한다. MCP 어댑터도 같은 확인을 거친다.
- 운영자 공용 키를 전제로 개인별 상한과 전체 상한을 함께 적용한다. 일반 사용자는 운영 상한을 올릴 수 없다.
- 모델 호출 전 예약과 사용량 정산을 DB에서 처리한다. PostgreSQL 6개 동시 요청에서 전체 한도 1회를 초과하지 않는 것을 검증했다.
- 운영자 화면은 회원 정책과 공용 사용량을 제공한다. 다른 사용자의 개인 문서 원문은 표시하지 않는다.
- 업로드 자료의 계정별·전체 보관량을 제한한다. 추출 텍스트와 base64를 포함한 보수적 추정이며 전체 DB 크기 제한은 아니다.

### 지원별 문서 준비와 내보내기

- 현재 버전을 기준으로 전략 승인, 문항/레쥬메 검수·잠금, 전체 검수, 최종 보관, 실제 제출을 확인한다.
- 부족한 단계의 버튼으로 해당 작업 화면을 바로 연다.
- 최종 보관 후에는 immutable 보관본에서 자기소개서 TXT, 레쥬메 PDF/DOCX, 버전 manifest를 ZIP으로 만든다.
- 다운로드는 실제 제출 완료를 기록하지 않는다. 동결 이후 원자료 변경이 이미 보관한 문서를 바꾸지 않는다.
- 현재 마감이 지난 공고를 다시 판정하고 행동 순위를 조정한다. 저장 당시의 공고 평가는 보존한다.
- 실행 기록에서 해당 지원 작업으로 이동하는 버튼과 오류 복구 화면을 추가했다.

### Astra 감사에서 발견한 오류 수정

| 문제 | 수정 및 검증 |
| --- | --- |
| 같은 우선순위의 프로필 사실 충돌이 기존 잠금 문서에 반영되지 않음 | 관련 문서를 재검토 상태로 전파하고, 최종 보관 시 현재 사실·출처를 재검사 |
| 업로드/기존 자료의 ownership 문자열로 검수·면접 흐름 중단 | 신규 자료 구조 통일, 기존 UNKNOWN 문자열 읽기 호환 |
| 같은 지원의 레쥬메 원본을 다시 쓰면 자신을 오래된 문서로 만드는 의존 관계 | 같은 지원은 구조 참고만 사용, 다른 지원은 유효한 원본 의존 관계 유지 |
| 레쥬메 재생성 시 보호 문구 누락 | 보호 문구 유지 여부를 검사하고 설정을 새 버전에 보존 |
| 실제 스키마만으로도 Groq 입력 한도를 초과한다고 오판 | gpt-oss 20b/120b에 공식 토큰 사전 기반 입력 추정 적용, 오프라인 배포 검증 |
| 공유 키 예산을 사용자마다 따로 소비하거나 개인 상한을 임의 확대 | 개인·전역 동시 예약 및 운영자 상한 적용 |
| 공유 사용자가 서버의 개인 seed를 가져올 수 있는 경로 | 개인 로컬 소유자만 사용 가능하도록 제한 |
| 외부 비교 실험 API가 공용 예산을 우회 | 공유 서비스의 해당 실행 차단; 기존 실행 통계 조회는 유지 |

Astra가 전체 감사에서 지적한 항목을 수정한 뒤 초대·인증·MCP·공용 한도·업로드·문서 묶음을 읽기 전용으로 재검토했다. 이 재검토 범위에서 추가 확정 P1/P2 회귀는 없었다. Astra가 테스트를 별도로 재실행하거나 운영 환경 전체를 인증한 것은 아니다.

Groq 입력 계산은 [공식 GPT-OSS tokenizer](https://github.com/openai/gpt-oss/blob/main/gpt_oss/tokenizer.py)와 tiktoken의 o200k_base 일반 텍스트 사전을 사용하고 여유분을 더한다. 사전의 SHA-256과 MIT 고지를 포함했다. 실제 공급자 사용량·무료 잔액은 아니며 [Groq 조직별 호출 제한](https://console.groq.com/docs/rate-limits)에 따라 429가 발생할 수 있다. 무료 소진 시 자동 유료 전환은 추가하지 않았다.
