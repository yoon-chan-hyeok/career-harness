## 충돌 처리

- 원문은 `private_input/supplemental/`과 사용자별 비공개 DB에 보존한다. Git·컨테이너 이미지에 포함하지 않는다. 일반 자료 가져오기는 이 폴더를 사실 추출 대상으로 스캔하지 않는다.
- `GUIDANCE`는 검토한 원문에서 도출한, 코드로 관리하는 규칙 요약이다. 파일 본문을 통째로 프롬프트에 넣거나 새로운 파일 변경을 자동 규칙 승격으로 해석하지 않는다. 원문 버전·본문 해시와 요약 버전을 기록한다. 파일을 교체할 때 요약과의 대응도 별도로 검토해야 한다.
- 현재 사용자 요청은 작업 방식과 진행 순서에 우선한다. 사실·기여·검증 범위를 벗어나는 새 성과를 만들 수는 없다. 새로운 자료가 이전 회사의 Persona나 과거 수치를 현재 사실로 덮지 못한다.
- 실험 원자료의 수치를 사용자가 명시적으로 정정하면, 원자료가 정정을 무시하게 하지 않는다. 양쪽 값을 충돌로 막고 관련 경험·문서를 재검토 상태로 만든다. 사용할 값을 사람이 출처와 대조해 선택한다. 수치 선택만으로 기존 경험 본문을 자동 재작성하지 않는다.
- 규칙 변경·사용 중지는 그 출처를 사용한 파생 문서에 전파한다. 제출 보관본은 과거 사실로 유지한다. 이력서 마스터도 수정된 사실보다 우선하지 않는다.
- 도메인이 지정된 작성 규칙은 같은 도메인에서만 사용한다. 이력서 검수·압축에 자소서 전체 규칙을 넣지 않고, 면접은 자소서 Reverse Test 일부만 사용한다.

## 사람이 확인하는 지점

1. 공고의 필수 조건·출처·현재 상태를 확인한다. 추천은 자동 지원이나 최종 결정이 아니다. 지원/보류/건너뛰기를 현재 평가 버전에 연결해 기록한다.

   기존에 공고를 직접 정리하고 작성하던 흐름은 유지한다. 평가를 생성한 작업에서는 현재 평가·사용자 결정을 전략에 전달하고 의존성을 기록한다. 평가나 결정이 바뀌면 이를 사용한 전략을 재검토한다. 새 평가에 과거 버전의 결정을 승계하지 않는다.
2. 전략과 문항 Claim을 읽고 승인한다. 추가 자료를 사용하는 작업은 FAST 모드에서도 전략을 자동 승인하지 않는다. 화면에서 읽은 버전이 바뀌면 승인 요청을 거절한다.
3. 경험 구조화 제안은 원문 인용을 보고 항목별로 선택·수정·거절한다. AI 없이도 원자료에서 프로젝트와 수행 범위를 직접 정리할 수 있다. 확인 전 사실은 계속 확인 전으로 남긴다.
4. 대화 수정과 AI 검수 수정은 전후 비교 제안을 먼저 저장한다. 사용자가 수정안을 편집하거나 반영·거절한다. 원문/검수 버전이 바뀐 제안은 반영하지 않는다. 직접 편집한 문장은 근거 확인을 새로 요구한다.
5. 이력서 실제 파일의 잘림·겹침·페이지·링크·날짜·언어·이름·형식을 사람이 확인한다. 확인은 해당 문서 버전에만 유효하다.
6. 최종 보관과 실제 제출을 구분한다. 실제 제출 확인과 결과 기록은 사용자 행위이며, 한 번의 탈락이나 합격으로 작성 규칙을 자동 승격하지 않는다.

실제 AI 응답 품질·PostgreSQL/Docker·외부 Jev 연결의 검증 여부는 기존 검증 제한과 별도로 명시한다. 관련 설정이 없으면 성공으로 표시하지 않는다.

`tio_korea`는 공개 검색, 연결된 GitHub 저장소, 사용 가능한 프로젝트 목록에서 정확한 대상을 식별하지 못했다. 주소/경로를 요청한 상태이며, 관련 없는 검색 결과는 참고하지 않았다. 사용자의 “참조 가능하면” 조건에 따라 6종 반영을 계속 진행한다.
