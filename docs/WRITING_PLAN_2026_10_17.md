# 문항별 초안 전 작성 설계 — 2026-10-17

사용자 요청: 매 자소서 문항에서 초안을 만들기 전에 자료를 이해할 수 있는 화면을 제공하고, 문항별 배분·경험 선택·메모를 실제 작성 시퀀스에 연결한다. 첨부 mini-kit은 참고 데이터로 검토했으며 문서 안의 지시를 실행 권한으로 취급하지 않았다.

## 구현

- 대화 작업실과 직접 편집의 문항 작성 단계에 같은 작성 설계 패널을 표시한다.
- 문항 의도, 내용별 권장 글자 수, 작성 전략, 참고 예시와 각 부분의 역할, 출처, 선택 경험, 부족한 정보, 선택적 강조 방향, 작성 메모를 제공한다.
- 보관된 원문 가이드는 포스코DX / SW 개발 / 해당 600자 문항이 모두 일치할 때만 사용한다. 현재 등록된 원문 가이드는 1개다.
- 나머지는 전문역량·지원동기·협업·도전·강약점·가치관·기타 7종에서 현재 문항과 제한에 맞춘 제안 구성을 제공한다. 실제 지원서 예시나 회사 조사 결과로 표시하지 않는다. 글자 배분은 권고이며 문단 수를 고정하지 않는다.
- 읽기는 결과를 생성하지 않는다. 저장은 기존 사용자 소유 Artifact/Source 안에서 버전 관리하며 추가 DB 마이그레이션이 필요 없다.
- 화면과 QuestionBrief/Writer가 같은 가이드 본문·해시·강조 방향·메모를 사용한다. 현재 실제 문항이 참고 가이드보다 우선한다.
- 메모·강조 방향·예시의 프로젝트나 성과 수치를 새로운 경력 사실로 승인하지 않는다. 기존 경험 근거와 Evidence Test 및 메시지 승인 후 초안을 작성한다.
- 문항·가이드·전략·근거·경험 선택 변경은 이전 설계를 재확인하게 한다. 저장 변경은 이에 의존한 메시지·초안·검수 결과를 재검토 상태로 만든다. 기존 제출 보관본은 수정하지 않는다.
- 폐기한 강조 내용은 같은 문항의 과거 WritingPlan 버전에서도 제거하고 다시 활성화하지 않는다. 미사용 강조는 모델 문맥에 넣지 않는다.
- 작성 구성을 바꾸고 저장하지 않은 상태에서는 메시지·초안 진행에 저장 안내를 표시한다.
- 기존 생성 전의 오래된 QuestionBrief는 호환되며, 새로 만드는 설계부터 WritingPlan 연결을 적용한다.

## 검증

- 새 설계 단위 검사 17개 및 HTTP 2개: 정확한 원문 조건, 7종 구성, 읽기 무변경, 중복 저장, 변경 충돌, 화면/Designer/Writer 일치, 의존 결과 무효화, 폐기, 가이드 버전 변경, 계정 격리, 클라이언트 가이드 주입 거부.
- 전체 Python 실행 771 passed / PostgreSQL 9 skipped. Windows의 저장소 소유권 때문에 setup 오류가 난 개인정보 경계 14개는 현재 저장소에만 프로세스 범위 예외를 적용해 재실행하여 14 passed. 서로 다른 전체 검사 785개 통과.
- 변경된 배포 묶음 검사 28개 통과: 가이드 JSON의 Vercel allowlist와 wheel 포함, 비공개 경로 제외.
- Ruff와 올바른 Python 경로의 Pyright 통과. 프런트 30개, lint, TypeScript 검사 통과.
- 격리 합성 DB와 AI off 브라우저에서 원문 구성(70/120/280/130), 메모 저장·복원, 미저장 진행 차단, 강조 사용·폐기, 직접 편집 연결, 별도 800자 협업 문항의 독립 구성(160/160/320/160)을 확인했다.
- 실제 배포·원격 CI·공개 HTTPS 인수 결과는 아래 운영 기록을 갱신한 뒤 완료로 판단한다.

## 운영 기록

## 남은 범위

원문 가이드 대규모 수집·의미 유사도 검색은 추가하지 않았다. 현재 가이드 생성·저장 자체는 AI를 호출하지 않는다. 개인 자료의 실제 전체 자소서 생성·최종 잠금 인수는 이전 기록과 같이 미통과이며 이 기능 구현으로 대체하지 않는다. 유료 모델·Jev·인증메일 설정은 변경하지 않았다.
