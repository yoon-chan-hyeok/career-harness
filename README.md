## 어떤 서비스인가요?

지원할 때마다 공고를 다시 읽고, 예전에 한 일을 찾고, 문항마다 어떤 경험을 쓸지 정합니다. AI에 작성을 맡겨도 기술 키워드만 보고 직무를 연결하거나, 내 역할과 성과 수치를 바꾸는 일이 생깁니다.

**Career Harness는 이 반복 작업을 지원 한 건의 흐름으로 연결합니다.** 공고에서 실제 맡는 일을 정리하고, 현재 확인된 경험을 근거로 연결합니다. 어떤 메시지를 보여 줄지 정한 뒤 문항의 의도와 권장 구성을 확인하고 작성합니다. 자소서와 이력서, 검수 질문과 수정 이력을 별도로 보관해 다음 지원이나 면접 준비에 이어 갑니다.

취업 준비 중 경험과 문서가 여러 곳에 흩어져 있거나, 초안의 표현을 어디까지 믿어도 될지 확인하고 싶은 사람을 위한 서비스입니다.

## 무엇을 할 수 있나요?

| 기능 | 이용자가 하는 일 | 남는 결과 |
|---|---|---|
| 경험 정리 | 프로젝트 자료와 본인 역할·수치·출처를 등록하고 확인 | 재사용할 경험과 근거 |
| 공고·직무 분석 | 공고와 회사 자료를 가져와 실제 업무와 경험을 대조 | 직무 분석·직접 근거·현재 공백 |
| 지원 전략 | 보여 줄 강점과 문항별 경험을 선택하고 승인 | 지원 전략·문항별 메시지 |
| 초안 전 작성 설계 | 문항 의도·권장 배분·예시를 읽고 경험·강조 방향·메모를 선택 | 화면과 작성 입력에 연결된 문항별 설계 |
| 자소서·이력서 작성 | 확인한 근거로 작성하고 문서별로 수정 | 문항별 초안·구조화된 이력서·버전 |
| 검수·최종본 보관 | 수치·기여·출처·문항 답변을 확인하고 최종본을 잠금 | 검수 기록·보관본·면접 준비 자료 |

**최종본 보관과 실제 제출은 별도입니다.** 채용 사이트에 자동으로 지원서를 제출하지 않습니다.

## 지원 한 건의 흐름

~~~mermaid
flowchart LR
    A["경험·공고 등록"] --> B["직무 분석·근거 연결"]
    B --> C["전략 선택·사용자 승인"]
    C --> D["문항별 설계·주장 검증"]
    D --> E["메시지 승인·자소서 작성"]
    C --> R["이력서 구성·작성"]
    E --> F["검수·수정"]
    R --> F
    F --> G["최종 확인·보관"]
    G --> H["면접 준비"]
~~~

문항별 설계는 자소서 경로이고, 이력서는 같은 현재 사실과 근거를 사용하는 별도 구성·검수 경로입니다. 경험이나 전략이 바뀌면 연결된 문서의 재검토가 필요합니다. 이미 보관한 최종본은 당시 상태로 유지합니다.

<details>
<summary>승인과 근거 검증은 어떻게 연결되나요?</summary>

전략 승인 뒤 문항별 의도·권장 배분·예시·경험·메모를 준비합니다. 이어서 핵심 메시지와 주장을 설계하고, Evidence Test가 선택한 원자료로 주장을 검증합니다. 사용자가 메시지를 승인해야 초안으로 진행할 수 있습니다. 검수에서 질문이나 수정이 생기면 해당 문서를 고친 뒤 다시 확인합니다. AI가 사용자의 승인이나 실제 제출 완료 확인을 대신하지 않습니다.

</details>

## 반복하던 판단을 어떻게 도와주나요?

| 고민 | 서비스에서 적용한 판단 |
|---|---|
| “RAG를 써봤으니 이 직무도 맞을까?” | 키워드와 함께 실제 산출물·핵심 업무·직접 경험·부족한 역량을 봅니다. |
| “이 문항에 어떤 경험을 얼마나 쓸까?” | 문항 의도와 권장 구성을 먼저 보고, 보여 줄 판단과 본인 행동을 배분합니다. |
| “예시처럼 쓰면 내 성과도 그렇게 되는 걸까?” | 표현 참고와 사실을 분리합니다. 예시의 프로젝트·기관·수치를 내 경력으로 가져오지 않습니다. |
| “팀에서 한 일을 내가 다 했다고 써도 될까?” | 본인 기여와 주장에 현재 근거를 연결하고, 부족하면 질문하거나 범위를 좁힙니다. |
| “내 역할을 정정했는데 초안은 그대로일까?” | 연결된 결과를 재검토 상태로 바꾸고 근거·메시지를 다시 확인합니다. |

현재 원문 가이드는 특정 회사·직무·문항·글자 제한이 일치하는 1개입니다. 다른 문항은 7종 유형에 따른 **제안 구성**을 제공합니다. 예를 들어 600자 문항의 70/120/280/130자 배분은 등록된 가이드의 권장 예시이며 모든 문항의 고정 공식은 아닙니다.

1. **[홈페이지](https://career-harness-web.vercel.app/)**에서 서비스를 살펴보거나 **[작업실](https://career-harness-web.vercel.app/workspace)**로 바로 이동합니다.

## 자기소개서 작성 단계

공고와 회사를 이해한 뒤 내 경험으로 지원 전략을 정하고, 문항별 설계 → 초안 → 검수 → 수정 → 최종 확정 순서로 진행합니다. 14~25단계는 문항마다 반복하고, 마지막에는 지원서 전체를 함께 확인합니다.

### A. 회사와 직무 이해 · 1~7

#### 01. 최신 JD 확인

지원할 공고의 원문, 출처, 마감일을 확인합니다. 필수 자격과 우대 조건을 구분하고, 이후 분석의 기준이 될 공고를 정합니다.

#### 02. 회사·사업·조직 조사

회사가 무엇으로 사업을 하고, 지원 조직이 어떤 문제를 다루는지 조사합니다. 공고만으로 알 수 없는 업무 배경을 보완하고, 확인한 사실에는 출처를 붙입니다.

#### 03. 과거·경력·유사 JD와 비교

현재 공고의 역할이 모호하면 과거 공고, 경력직 공고, 현직자 설명과 유사 직무를 비교합니다. 반복해서 요구하는 역량을 찾되, 과거 자료와 현재 사실을 구분합니다.

#### 04. Why Now: 지금 채용하는 이유

사업·조직 상황과 채용 내용을 연결해 지금 이 역할이 필요한 이유를 정리합니다. 회사가 밝힌 사실과 내가 세운 가설을 나누고, 근거가 부족한 부분은 미확인으로 남깁니다.

#### 05. Actual Output: 입사 후 만들 산출물

입사하면 어떤 분석·시스템·보고서·운영 결과를 만들어야 하는지 적습니다. 기술 목록을 실제 업무 결과로 바꾸어, 어떤 경험을 증명해야 하는지 정합니다.

#### 06. 본업·전문 분야·도구 분리

직무의 본업(Base Profession), 전문 분야(Specialty), 사용하는 도구(Tool)를 구분합니다. 특정 기술이 등장한다는 이유만으로 직무 전체를 그 기술의 개발·연구 역할로 해석하지 않습니다.

#### 07. 핵심 역량과 차별점 구분

업무를 맡기기 위해 반드시 필요한 Main Skill과, 추가 강점이 되는 Differentiator를 나눕니다. 자기소개서에서는 핵심 역량의 증명을 먼저 세우고 차별점을 더합니다.

### B. 근거와 지원 전략 · 8~13

#### 08. Direct / Adjacent / No Evidence 매핑

각 업무에 내 경험을 연결합니다. 직접 수행한 경험은 Direct, 옮겨 쓸 수 있는 인접 경험은 Adjacent, 증명할 자료가 없으면 No Evidence로 구분합니다.

#### 09. Fatal Gap과 대응 판단

필수 자격이나 핵심 업무에서 부족한 부분을 찾습니다. 지원 판단에 영향을 주는 공백과 보완 가능한 공백을 나누고, 지원 여부와 설명할 한계를 정합니다.

#### 10. 현재 Fact 재확인

경험의 원자료, 직접 맡은 범위, 성과 수치의 조건을 다시 확인합니다. 이전에 정정한 내용과 관련 교훈도 검토해 같은 과장이나 오류를 반복하지 않게 합니다.

#### 11. 맡길 일 한 문장

회사가 나를 채용하면 어떤 일을 맡길 수 있는지 한 문장으로 적습니다. 추상적인 장점보다 실제 업무와 이를 뒷받침하는 경험이 드러나게 합니다.

#### 12. Persona 도출

이번 지원에서 어떤 사람으로 기억될지 정합니다. 직무의 본업과 내 근거를 바탕으로 주력 역량·차별점을 묶어, 지원서 전체의 방향을 잡습니다.

#### 13. 문항 전체의 역할 배분

각 문항이 증명할 역량, 핵심 메시지, 사용할 경험을 먼저 나눕니다. 같은 프로젝트를 다시 쓰더라도 다른 판단과 기여를 보여 주고, 숫자·메시지·결론의 반복을 줄입니다.

### C. 문항별 작성 설계 · 14~20

#### 14. 문항 의도 해석

질문이 실제로 확인하려는 역량과 반드시 답해야 할 내용을 정리합니다. 지원동기·협업·도전 등 문항 유형에 맞춰 답변의 중심을 잡습니다.

#### 15. 문항에 쓸 Fact 재확인

이번 문항에 사용할 대표 경험과 보조 근거를 고릅니다. 원문, 직접 기여, 수치, 한계와 하지 않은 일을 확인해 쓸 수 있는 범위를 정합니다.

#### 16. 과거 자소서와 표현 참고

과거 글에서 도움이 되는 논리 순서와 말투를 찾습니다. 표현 구조는 참고하되, 예전 회사명·수치·기여를 현재 사실처럼 가져오지 않습니다.

#### 17. Operational Value로 번역

기술적으로 한 일이 업무에서 어떤 가치가 있는지 설명합니다. 실험 결과와 실제 운영 효과를 구분하고, 측정하지 않은 매출·시간 절감 등을 성과로 만들지 않습니다.

#### 18. Provisional Claim: 핵심 주장 후보

문항에서 독자가 기억해야 할 핵심 메시지와 보조 주장을 제안합니다. 각 주장이 어떤 경험으로 증명되는지 연결하고, 문항 의도와 지원 전략에 맞는지 확인합니다.

#### 19. Evidence Test → Claim Lock

주장을 근거로 뒷받침할 수 있는지, 더 강한 근거가 있는지, 면접에서 설명할 수 있는지 검토합니다. 부족한 부분을 보완한 뒤 이번 문항의 핵심 메시지를 확정합니다.

#### 20. PODAEIJ로 서사와 분량 설계

Problem → Observation → Decision → Action → Evidence → Insight → Job Relevance 중 문항에 필요한 요소를 골라 이야기 순서를 정합니다. 문항 의도, 참고 예시의 역할, 권장 글자 배분을 확인하고 문단별로 무엇을 쓸지 설계합니다. 모든 요소를 일곱 문단으로 넣을 필요는 없습니다.

### D. 초안·검수·수정·확정 · 21~26

#### 21. 초안 작성

확정한 메시지와 근거, 문단 구성, 글자 제한에 맞춰 초안을 씁니다. 첫 부분에서 질문에 답하고, 경험 속 판단과 행동이 주장을 어떻게 증명하는지 이어 갑니다.

#### 22. Fact / Ownership 검수

문장 속 사실·숫자·직접 기여를 원자료와 대조합니다. 팀의 결과를 개인 성과로 확대하거나, 실험을 실제 운영 성과로 바꾼 표현이 없는지 확인합니다.

#### 23. Reverse Test: 내 글을 설명할 수 있는가

강한 주장과 불명확한 부분에 예상 질문을 던지고 답해 봅니다. 설명이 막히면 근거를 보완하거나 문장을 고치고, 증명할 수 없는 부분은 한계로 인정합니다.

#### 24. Red Team: 채용담당자 관점으로 읽기

질문에 직접 답하는지, 본업이 먼저 보이는지, 채용 후 맡길 일이 떠오르는지 검토합니다. 문항 사이의 반복·모순을 확인하고, 본업을 원하는 이유와 경험이 그 역량을 증명하는 이유도 다시 점검합니다.

#### 25. 압축과 부분 수정

검수에서 찾은 문제를 고치고 글자 제한에 맞게 압축합니다. 핵심 판단·근거·직무 연결을 보존하면서 불필요한 기술 설명과 반복을 줄이고, 수정한 부분을 다시 검수합니다.

#### 26. Lock: 최종본 확정

본문·근거·검수 답변이 서로 맞는지 확인하고 문항별 최종본을 확정합니다. 지원서 전체의 일관성과 분량을 마지막으로 확인하며, 최종본 보관과 실제 제출은 구분합니다.
